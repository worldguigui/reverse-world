# 世界图志 · 世界观时间轴工具

> 基于 **Three.js + Vite** 的架空世界构建工具：在球体上画一张平面地图，或直接生成**真实地球地形**，用**一根游标**串起世界的演变（沧海桑田），按经纬度放置**事件 / 路线 / 势力区域**，还能用**地图工坊**像画等高线图一样捏出自己的山川河流。球面画地形、路线与区域，事件在时间轴与编年史上一条条翻。
> 地球只是一个示例世界——它可以是任何世界。
>
> **文档体系**：本 README 分为「架构介绍」与「版本迭代记录」两部分；配套文档见 [`docs/README.md`](docs/README.md)（更新规则）、[`docs/ADR.md`](docs/ADR.md)（重大决策）、[`docs/DESIGN.md`](docs/DESIGN.md)（当前阶段方案）、[`docs/TEMP.md`](docs/TEMP.md)（临时需求）。所有文档遵循「**区域顶部插入**」更新策略，最新内容始终在顶部。

## 第一部分 · 架构介绍

### 1. 技术栈与快速开始

- **技术栈**：Three.js `^0.186.1` + Vite `^8.3.4` + React `^19.3.0` + Zustand `^5.0.15`；原生 JavaScript（ESM，非 TypeScript）。
- **前端框架**：React + Zustand，仅接管 UI 层与状态层（`core/`、`view/` 不进框架）；构建产物相对路径，可静态部署。
- **命令**：`npm install` / `npm run dev`（http://localhost:5173）/ `npm run build`（dist/）。
- **验证脚本**（`scripts/`，依赖本机 Edge + 已启动 dev server）：`node scripts/verify-terrain.mjs`（地形端到端）、`node scripts/ui-test.mjs`（UI 交互）、`node scripts/shot.mjs`（截图）。
- **编程入口**：浏览器控制台 `window.world`（由 `src/api.js#installAPI` 挂载），提供 `help()/loadSample()/getCursor()/setCursor()/stepCursor()/jumpToEvent()/showChronicle()/generateRealEarth()/openWorkshop()/paintTerrain()/sampleTerrain()/listEvents()/addEvent()/addRoute()/addRegion()/flyTo()/where()/resetView()`，以及人物与章节的 `addCharacter()/listCharacters()/eventsOfCharacter()/addGroup()/listGroups()/eventsOfGroup()/filterByGroup()/filterByCharacter()/clearFilter()` 等。

### 2. 核心概念

世界分四层，用剧场的说法各司其职：**舞台**（球长什么样，与时间无关）、**布景**（路线、区域）、**演员**（事件）、**追光**（游标，此刻看哪一年）；**人物**是演员表上的名字，**章节**把戏分成几幕——这两样都不上台。

- **世界项目** = 一张脸（地图）+ 内容（事件 / 路线 / 区域 / 人物 / 章节），整体是一个可 JSON 序列化的对象（`src/core/project.js#createProject`）。
- **舞台只有一张脸**：球体不随时间换皮。`baseRasterId` 指向唯一那张地图（栅格地形），为空就是**深色空球**。**拖游标不换脸**——这是刻意的，地图是一张图，它跟时间没有关系。地图就是能在 2D 工坊里编辑、同时显示在 3D 球面上的那个东西；没有第二种「只能贴图、不能编辑」的底图。
- **游标**：一个**数值年**（`cursor`，负数为公元前，允许小数）。它不是项目数据，而是「此刻在看哪一年」，所以不进 `project`；拖动它只翻内容的可见性，一个像素都不重画。
- **内容生命周期**：带时间的内容（事件 / 路线 / 区域）都有 `from` / `to` 两个**年份**（留空 = 该端开放，两端都空就是「常驻」）。可见性判定唯一位置 `project.js#isActiveAt`（闭区间 `from <= cursor <= to`），三类内容共用这一条判据。
- **事件**：一条事件是「哪一年发生了什么」，可以带坐标、也可以不带——**纯叙事事件不上球**，只进编年史（长卷里标注「无地点」）。**事件不铺点**：事件一多，球面会被点铺满，也会让人以为「点上去能选中」。事件的入口只有时间轴刻度与编年史长卷两处，球上只把**选中那一条**的坐标点亮成一枚光点，改选别人它就灭。事件还是**时间轴刻度的唯一来源**（`core/timeline.js#timeTicks`）——路线与区域虽然也带年份，但不画刻度。
- **时间轴与编年史**：轴的定义域由内容自己的 `from`/`to` 算出来（`timeDomain`），没有任何需要人维护的槽位——给某条内容填上时间，轴就长出来一截。轴上不铺标题（挤在一起没法看），标题在**编年史长卷**里按时间铺开。
- **人物与章节**：人物是事件的参与者，不是地点上的东西——所以不上球、没有存续区间，`born` / `died` 只是生平，不参与在场判定。章节是事件的归类，本身不带年份，标签上的范围（`1914–1919`）由组内事件的年份算出来。两者与事件的关联都**只写在事件那一侧**（`characters` / `groupId`），人物卡上那张「涉及的事件」是现算的——反向关系是求值，不是数据。
- **视图条件**：`viewFilter = { groupId, characterId }` 决定「此刻在看什么」，两个都可空，同时给就是交集。指向章节时是真的翻章；按人物筛出的那一组是**算出来的**，用完就没了，不落盘、不进 `groups`。两者共用一条筛选路径——收窄换的只是「谁在场」，一个像素都不用重画。
- **地图（双通道）**：等距圆柱投影的**高度 + 水**网格（**2048×1024**，赤道约 20km/格）。高度是多高（归一化单位，0=海平面，[-4,4] 设计范围），只决定球面几何；水是 0..255 的连续浓度，只决定颜色。**两者互相独立**，所以蓝色高山、绿色盆地都画得出来。渲染成「陆地色带 + hillshade + 水下渐变」贴图，**GPU 顶点位移让山从球面上真正隆起**。
- **真实地球的两张原料**：`earth-relief.png` 给高度，R+G 打包 16-bit，**海陆同一个数**（海底就是负高度，最低约 −10km）；`earth-water.png` 给水，白=陆地、黑=海洋/湖泊，海陆掩膜与 `ne_50m_rivers.geojson` 的河网一起写进水通道。合成就两件事：高度整张照搬，水按掩膜置 0 / 255——没有海陆分支、没有第二套公式、没有符号夹取。
- **水**：海、湖、河不分家，都是水通道；颜色按所在高度渐变（越低于海平面越深），海平面以下的水面不打光、保持平展，水线才不会跟着山体阴影抖动。
- **地图工坊**：全屏栅格画笔，分「形态」（抬升/降低/抹平，只写高度）与「水」（加水/去水，只写颜色）两组，硬笔/软笔，笔刷最小可到**一格**；可切换黑白水陆掩膜检查水的分布。每笔实时反映到球体；画布支持滚轮缩放与拖动平移；撤销/重做同时恢复两个通道；一键从真实地球生成。

### 4. 关键机制（架构要点）

- **GPU 地形位移**：`view/globe.js#_buildSphere` 在 `MeshPhongMaterial.onBeforeCompile` 注入顶点着色器——高度纹理（R+G 打包 16-bit）用双线性采样（线性色空间、不生成 mipmap），`transformed += normalize(position) * unpackHeight(texture2D(uHeightTex, uv).rg) * uExaggeration`；法线用高度场邻域差分扰动。位移只在 GPU，射线拾取对逻辑球面（未位移的 `globe.sphere`），放置内容天然自洽。
- **贴图对准**：`utils.js#latLngToVec3` 与 `SphereGeometry` 的 UV 展开一致。
- **球面弦陷防护**：区域按边长 ≤2° 递归四分割（`view/regions.js#pushSubdivided`，深度上限 6），路线走大圆弧 slerp 细分（`view/routes.js#arcPositions`，≤2°/段）。
- **球面拾取只有路线与区域**（`main.js#pickAt`）：走射线，两者都浮在地表之上，各自按地平线判据筛一遍（`raycaster` 不理会 `visible`）。**事件不在球上拾取**——球面只负责画，事件的入口是时间轴刻度与编年史长卷。地名曾经在球上有自己的一套拾取（贴地四边形 + 屏幕空间查点），那是它的画法决定的；整层拿掉之后，这条路径也就不需要了。
- **自由翻滚的相机**（`view/camera.js`）：OrbitControls 的球坐标把 `phi` 从相机位置 `acos` 出来，恒落在 `[0, π]`，绕极点时被夹住——这是表示法的限制，参数怎么调都过不去。所以旋转改由自己用四元数做 trackball：拖动时按「屏幕右 / 屏幕上」两个轴构造四元数，**同时**乘到相机的位置与 `up` 上。相机永远看原点、且 `up ⊥ 视线`，两者同步旋转后这个关系不变（OrbitControls 自己的坐标系里 `phi` 恒为 π/2，它的往返换算仍然精确），于是可以越过南北极、把地平线转歪。缩放仍交给 OrbitControls——距离计算与朝向无关，没必要重写。自转也改为绕世界 Y 轴（南北极）而非相机上方向：翻过球之后两者不一致，用后者会变成绕屏幕竖线打转。转晕了用 🧭 复位视角 / `world.resetView()` 回到正北朝上。
- **工坊画布视图**（`ui/workshop-session.js`）：画布按「一格一 CSS 像素」写死尺寸，缩放平移全走 CSS `transform: translate() scale()`，**不动画布分辨率**——改分辨率等于重采样，图会糊。缩放锚点直接用画布自己的 `getBoundingClientRect()` 算：它返回的是**变换后**的矩形，于是 `toGrid` 那条「屏幕坐标 → 网格坐标」的换算在任意缩放下自动成立，不必手写变换的逆。
- **栅格存储**：整张地图编码为一张 PNG（`core/raster.js#encodePNG`：R+G=16-bit 高度 [-4,4]，B=水 0..255），地图记录上的 `format: 2` 标明这套通道约定；没有该字段的旧项目按旧规则解码（B 是河流，并进水通道，再按高度符号补出海）。IndexedDB 单条记录 500ms 防抖自动保存，导出为内嵌图片的单文件 `.world.json`（`core/storage.js`）。
- **数据驱动渲染（三级信号 + 独立舞台信号）**：拖游标必须是零重建的，这一条决定了信号的切法。一条内容的**样子**只由它自己的数据决定，与游标在哪一年无关——所以游标一变，只需要翻一批开关。
  - `store/world.js#contentRev`（**内容变了**：增删改事件/路线/区域/人物/章节）→ `bridge.js#rebuildLayers()` 重建贴图、几何、材质；
  - `store/world.js#derived`（**游标走了 / 视图收窄了**：同一批内容换了一批在场者）→ `bridge.js#applyActiveLayers()` 只翻 `visible`，成本是 N 次布尔赋值。筛选就叠在 `buildDerived` 里面（`activeEvents` 的输入是「在场 ∩ 属于当前视图」），所以翻章与拖游标走的是同一条路，`bridge.js` 一行都不用改；
  - `store/ui.js#layoutEpoch`（**只是地形变了**：工坊画笔、`paintTerrain`）→ `bridge.js#relayoutLayers()` 把已有对象重新贴回新地表，derived 快照与全部光点贴图一概不动。
  - 与此正交的是 `store/ui.js#stageEpoch`（**换脸了**：换地图、载入项目）→ `bridge.js#applyStage()`，与游标完全无关。`session.stageToken` 是异步解码的竞态守卫：换地图要等 PNG 解码，等待期间用户若又换了一张，先回来的那次作废。
  - 实测：连续 400 步推游标共 19.2 ms（**0.048 ms/步**），路线的材质 / 纹理 UUID 全程不变——这就是「拖游标不卡」的根据。
- **一帧三趟渲染**（`view/render-layers.js` 定义层号，`main.js#render` 按序渲染三遍）：
  1. `LAYER_SCENE` — 球体、大气辉光、星空，正常写颜色与深度；
  2. `LAYER_MASK` — 与球面同半径的光滑球（`globe.js#_buildOverlayMask`，`colorWrite: false`），只写深度。渲染前 `clearDepth()`，于是它盖掉的是一张「没有山、只有球」的理想深度图；
  3. `LAYER_CONTENT` — 事件光点 / 路线 / 区域贴着这张深度图做测试。
  这样山挡不住内容（掩膜球没有隆起），而转到球背面仍会被正确遮挡（球体本身还在）。
- **材质回收桶**（`view/material-bin.js`）：three 用引用计数管 GL 程序，整层重建时若把旧材质 `dispose()` 掉，程序会跟着销毁、下一帧重新编译链接（实测一次重建 275ms）。桶把退下来的材质留下来复用，程序就一直在。图层重建路径上必须走它。
- **补间管理器的重入**（`utils.js#TweenManager`）：回调里可以再开动画（跳一条事件 = 设游标 + 选中 + 飞过去，最后那一步本身又是一段补间），所以 `update()` 不能就地过滤自己的数组——那样算完一圈会把回调期间新加的动画一起写掉，这次飞行就凭空消失了。实现改成先把待办挪出来、算完再收回，取消用 `dead` 标记传给还在手上的那批。
- **状态与视图分离**：UI 状态全在 `store/` 里（可序列化），three 对象与 `TerrainGrid` 等大 buffer 在 `session.js`；`bridge.js` 单向订阅 store 驱动三维，React 组件单向订阅 store 渲染自己，两边不互查 DOM。事件光点每帧的屏幕尺寸也**不进 store**：它只跟相机有关，与内容无关，逐帧写入 store 等于每帧触发一次 React 重渲染。

### 6. 已知限制

- **高程源是 10km 级的 Terrarium 瓦片**：`earth-relief.png` 由 Terrarium z=4 瓦片重投影而来，一瓦片约 10km/像素；在 2048×1024 的网格上，赤道一格约 20km，峰值（珠峰一类的窄峰）会被重采样削掉一些。要更陡、更尖的地形得换更高层级的瓦片或 ETOPO 原始数据，`core/raster.js` 只管高度，换数据源不牵动掩膜与渲染。
- **海岸线的精度与地形同级**：`earth-water.png` 已升到 2048×1024（Natural Earth 10m 多边形栅格化），与高度网格一一对应；一格仍约 20km，再往里放大就是像素放大。要做更细的海岸线，得同时提高掩膜与高度网格的分辨率。
- **掩膜以高程零点为准做最后对齐**：Natural Earth 与 Terrarium 是两套独立数据，20km 一格不可能逐格一致。`gen-mask.mjs` 把海洋里高度达到 16 位零点（32768）的格子改判为陆地——南极浮冰架、格陵兰沿岸小岛与远洋小岛因此不再以「水色 + 正高度」凸出水面；海岸线在少数地方比 Natural Earth 原图外扩，南极冰架会一直补到冰架外缘。湖泊与河流保持水色：它们是海拔高于 0 的水，不是海洋凸起。
- **两极的浮雕来自旧图**：Terrarium 是 Web Mercator，只覆盖 ±85.051°；`gen-relief.mjs` 用旧的 `earth-topology.png` 补南极、北冰洋则沿用瓦片边缘值。那两圈不是同一套 16-bit 数据，精度低于中低纬。
- **再往里放大就是纯放大像素了**：相机推到球心 1.25 倍球半径即停住，之后靠收窄视场角继续放大，一直能放到 67 倍（见 v0.0.8）——倍数是给够的。但一个球只有一张 2048×1024 的纹理，收到最窄一档时一个地形格要摊到一百多屏幕像素，画面自然发糊、海陆边界凝成一格格台阶。要真看清地面，得让视野里那块地**另有更细的图**：按需取瓦片/补丁（视口内才拉高分辨率，视口外维持粗档），再配更高分辨率的高程源。真实地图服务能一路放大到这个程度，靠的正是每级一张更细的图加全球米级影像，不是过滤器更聪明。
- 河流与海共用一条水通道，没有独立的河网结构：真实地球的河来自 Natural Earth 折线，手画的河只是细的水笔。水不随坡向汇流、不参与高度，D8 算法待做。
- 跨 ±180° 勾画的区域三角剖分可能出错（`buildFillGeometry` 未拆线；`buildBorderGeometry` 已按短弧处理）。
- 地图切换为硬切（交叉淡化待做）。
- **没有「地点」这一等实体**（见 v0.0.13）：地名印刷留待日后作为一层外挂（行政区图层）接回来。在那之前，一个地方要「在场」，写成一条事件——事件本来就有坐标、有配图、有存续区间，而地点与事件原先的差别只在谁上球、谁画刻度（v0.0.9 之后两者都不上球）。**代价是标一个位置就不再是件轻量的事**：事件一定会占掉时间轴上的一个刻度、并进编年史长卷，而只想在地图上点一个地名的人并不想讲一件事；另外事件是点、区域是面，一笔带过的地名也没法画成区域。
- **同年多条事件时刻度叠在一起**：刻度按事件的年份落位，同一年里的几条落在同一个 x 上，鼠标只有最上面那一个点得中。逐条读的入口是底部的 ◀ ▶：按一下换一条，并把游标与检查器一起带过去。轴没有「槽位」这个概念，刻度叠置是这个模型的直接后果。
- 轴是按年份**线性**铺开的，年份跨度大的世界会把内容稀疏的段落拉得很快（改成均匀分布是「非线性压缩轴」，属于另一个需求）。示例世界收在一战这六年里，正是为了让刻度排得开。
- v1 项目导入时只保留**最后一张**地图与地形，旧模型里的**地点**（`entries`）也不再保留：v1 是逐时间点各存一套舞台，v2 的球只有一张脸，多出来的那几套会丢掉；地点则是这一等实体本身已经取消，硬塞成事件只会把地名表混进叙事（事件 / 路线 / 区域 / 人物 / 章节一条不丢，时间点转成事件）。旧项目里的**图片底图**同样不再保留——它只能贴不能编辑，与地图是两条管线，已整体移除。
- 无单元测试框架（仅 scripts/ 三个 E2E）；`main.js#main` 仍是约 350 行的组装函数（UI 与状态已外移，剩下渲染基础、鼠标键盘交互与启动）。

2. **删掉图片底图上载**。世界概览里的「上传底图 / 清除舞台」、`project.maps / baseMapId`、`addMap / getMap`、`applyStage` 里的图片分支、`Globe#setMap` 与占位贴图一并删除。图片只能贴、不能编辑、也没有再展示的入口，与地图是两条管线——只留一条。
3. **术语对齐：底图 = 地图 = 2D 可编辑、3D 可展示的那张脸**。「引擎自带的地球贴图」这个概念删除；项目里只有 `baseRasterId` 指向的一张 `rasterMaps` 地图。没有地图时球是**深色空球**：`Globe#setBlank()` 把颜色贴图换成 1×1 深色 `DataTexture`、高度换成 1×1 黑图，shader 的 `USE_MAP` 分支保持编译结果不变，换脸不触发重新编译。世界概览只报「当前：地图 · X」或「当前：深色空球」，按钮是「编辑地图 / 画一张地图」与「从真实地球生成地图」。
4. **海底/河床不再是平的**。旧管线在海上没有高程信息，只能按离岸距离造深浅，并在 32 格以外把深度封顶在 **−0.45**；实测 **40.7%** 的地形格落在同一个值上——工坊里把水笔涂成 0、去掉整片海洋之后，露出来的就是这块平板。现在删掉两套公式（陆地一套、海洋一套）、海岸符号夹取与放宽颜色范围，合成只剩两句：`height` 直接取 16-bit 高程图（海陆同一个数，海底就是负高度），`water` 取海陆掩膜（陆地 0、水 255），没有海陆分支、没有 clamp、没有第二套公式。

### v0.0.11 长卷高亮改认选中，不再按游标推（2026-10-16）

1. **症状**：在长卷里单击一条事件、或按 ◀ ▶ 翻，**长卷上亮着的**与**检查器里显示的**不是同一条。
2. **根因是两个信号各说各的**。长卷的高亮当时由游标推出来——`Chronicle.jsx` 里 `for (const t of ticks) if (t.from <= cursor) currentId = t.id`，即「游标之前**最后一条**」；而检查器读的是 `selection`。点击与 ◀ ▶ 走的都是 `jumpToEvent`，它确实把两件事一起做了（`setCursorYear(ev.from)` + `select({ kind:'event', id })`），可**游标是一个纯年份，里面装不下「是哪一条」**——`ev.from = 1914` 一写进去，链式查找就只剩年份可用，而 1914 那一年挤着 9 条事件，循环扫到最后必然停在末条上。
3. **量化**：逐条点开示例世界的 32 条事件，**26 条对不上**；恰好对上的 6 条正是**每年最后一条**（圣诞节停战 / 戈尔利采攻势 / 坦克第一次开上战场 / 康布雷战役 / 贡比涅停战 / 凡尔赛条约）——这是根因的直接指纹。按 ▶ 连按 8 下**8 次全错**：游标一直停在 1914，高亮便一直钉在当年的末条上。第三种入口「只拖游标不换选中」也会让两者错开（那一条是设计使然，但同源）。
4. **改法**：高亮只保留一个含义——**检查器里正在讲的就是它**。`currentId` 直接取选中的事件 id，游标彻底退出高亮这一路；选中的不是事件（点球面、选路线区域）时一条都不亮。游标留下的那一半是**淡出**：`ahead`（`t.from > cursor`）照旧，管的是「还没走到」。顺带修好一个连带的毛病：`activeRef` + `scrollIntoView` 挂在 `currentId` 上，原先单击一条同年的事件会把长卷滚到**当年末条**去，现在滚的是你点的那条，长卷刚摊开时也会先滚到选中那条。
5. **实测**（`world.showChronicle(true)` 后逐条比对 selection 与 DOM 上 `.at-cursor`）：逐条点开 32 条 **0 条对不上**；▶ 连按 8 下 8 次全一致、且**同一时刻只有一条亮**；拖游标到 1918 时高亮仍与检查器一致；改选区域后**一条都不亮**。
6. **底部读数只报年份，不再报事件标题**（`Timeline.jsx`，原 `latest` 那段整个删掉）。原来那行读数的规则与长卷同源、但取的是**当年第一条**（`t.from > best.from` 是严格比较，同年不更新），于是选中「马恩河战役」时左下角写着「1914 萨拉热窝事件」——同一件事的第三个信号，又一次各说各的。**「讲的是哪一条」已经有长卷高亮与检查器两处**，第三处再报一遍只会多一个会走样的地方，所以这里收回到它的本职：游标停在哪一年。`ticks` 为空时的「还没有事件」提示保留（那种情况下轴由带区间的地点撑出来，确实一条事件都没有，得说一声）。`.tl-readout` 的 `min-width` 随之从 132px 收到 78px，轴多出五十几个像素。
7. **验收**：`scripts/ui-test.mjs` 47 项、`scripts/verify-terrain.mjs` 12 项全绿，`npm run build` 通过、无运行时报错。第 10 组用例补了一条承重断言——**一边翻一边比对长卷高亮与检查器标题，并数亮了几条**，这类「两个信号各说各的」不钉住最容易悄悄烂回去。

### v0.0.10 点开一条事件时镜头落到事件档位（2026-10-16）

1. **问题**：`jumpToEvent` 一直只调 `flyTo(lat, lng)` 不带距离，`flyToLatLng` 便取 `toDist = 距离 ?? 当前距离`——**只把球转过去，推拉与视场角一概不动**。量出来的后果：出厂视角下点开凡尔登，相机从 30°,105° 转到 49.16°,5.38°（方向对了），但距离恒为 3、fov 恒为 45°，一整颗球上什么也没「近」起来；放大到 60 档再点开，方向同样转了，可距离已经顶在 1.25 上，看上去就只剩画面中心挪了一下。
2. **改法**是把这里接到既有的**档位**上：`flyToLatLng` 新增可选 `level`，给了就由 `_levelToState` 把档位拆成「相机距离 + 镜头倍率」两段，飞行途中距离与视场角一起插值落定。原来那份换算完整地长在 `_applyLevel` 里，现在抽成 `_levelToState` 由滚轮与飞行共用，两条路走的是同一套档位定义。
3. **档位是乘法量**（每一档都是同一倍放大），所以插值按等比走：`fromLevel × (toLevel/fromLevel)^k`。实测从 1 档推到 8 档的轨迹是 `1.0 1.3 2.3 4.9 7.2 8.0`，从 60 档退回 8 档是 `58.5 48.9 27.5 12.9 9.0 8.0`（每 200ms 采一次），与解析的等比序列逐点吻合——收拢速度全程一致，不会两头慢中间猛。
4. **落点是固定档位**，不是「在当前基础上再推近一点」：这样从哪一档点开一条事件，看到的都是同一个尺度。起飞档位实测 1 / 8 / 20 / 60 四种，落点全是 8.0；方向也照旧转到位（都是从 30°,105° 到凡尔登的 49.16°,5.38°）。本来就在 8 档时，飞行退化成只转方向、镜头一动不动的老行为。
5. **默认 8 档，可调**（`config.camera.eventLevel`，画面设置「📷 视角」里多一根滑块，1–64）。8 档正好是「相机推到最近档、视场角还是出厂那个」，赤道上每度 75.8 像素、一个地形纹素 13.3 像素——2048 高度图还清楚的最大一屏。实测把凡尔登定在 8 / 12 / 16 / 24 四档出图比过：16 档往上水面边缘与地形已经是纯像素放大，24 档只剩色块。想更近可以往上调，代价就是这个。
6. **`world.where()` 顺带回报 `level`**（`camera.js#getLatLngZoom`），档位从此是能读能验的量，探针就是靠它量出上面那些轨迹的。
7. **验收**：`scripts/verify-terrain.mjs` 12 项、`scripts/ui-test.mjs` 46 项全绿，`npm run build` 通过、无运行时报错。`flyToItem`（检查器里的「飞到 / 定位」）与双击球面仍走原来的 `distance` 那条路，本次没有动。

### v0.0.8 相机推到底之后收镜头接着放大（2026-10-16）

1. **推近分成两段：相机先推向球面，推到底之后相机停住，改收窄视场角继续放大**（`view/camera.js#_applyLevel`）。相机只能推到一定高度（球心外 1.25 倍球半径），再近就进到球里了；可「推镜头」与「放大」本来就是两件事——相机停住之后收窄视场角，画面照样接着放大。两段合成同一个**档位**（相对出厂视角在屏幕上看到的大小），滚轮一律按档位走，所以两段都是匀速的。实测从出厂视角一路推到顶：相机由距离 3.0 推到 1.25（**8 倍**），视场角由 45° 收到 5.6°（再 **8 倍**），**合计屏幕放大 67 倍**，全程每格滚轮稳定 **+10%**（相机段第 21 格到底，此后档位全走镜头）。
2. **滚轮改由自己接管**（`view/camera.js#_onWheel`）。OrbitControls 的滚轮只会推拉相机，推到底就没有了，接不住「相机不动、只放大」这一段。它的滚轮监听挂在 canvas 的冒泡阶段，本类**先注册**即可用 `stopImmediatePropagation` 拦下来。`enableZoom` 保持打开，双指捏合照旧走 OrbitControls，不受影响。滚轮打断进行中 flyTo 的逻辑一并挪进这个处理函数——同一元素上的后续监听会被上面那个拦截一并挡住，再挂一个也收不到。
3. **旧存档再也盖不掉代码里的缩放上下限**（`config.js#dropCodeOwnedKeys`）。这两项不是设置面板里能改的，只是借 `config` 放着方便取用，可它们照样会被存进 localStorage，而载入时是存档盖默认值——于是改了代码却不生效，看着像没改。凡是「用户改不了、只吃代码」的项都该照这个办法挡一道（`fov` 是用户可改的，仍然听存档）。
4. **相机最近档 1.35 → 1.25**：相机多走一点，镜头就少收一点，同样倍数下画质更好。1.25 时一格地形约占 13 屏幕像素（原 9.5）。放大上限由 `view/camera.js#OPTICAL_MAX` 一个常量管着（现为 8，即视场角最窄到 45°/8 ≈ 5.6°）。
5. **验收**：`scripts/verify-terrain.mjs` 与 `scripts/ui-test.mjs` 全绿、无运行时报错，`npm run build` 通过。滚轮梯子、原路退回、存档覆盖都用探针量过；最窄视场角下的截图确认地球边缘、大气与地名都正常，画面只是纯放大。**上手时踩到一个自己写的 bug**：档位公式里镜头倍率乘反了（收窄视场角是放大，该乘不该除），结果档位推上去又掉回来，卡在距离 1.25 与 1.275 之间来回跳、一格都进不去——探针打出来的梯子一眼就看出来了。

### v0.0.7 地形升到原生分辨率（2026-10-16）

1. **全局地形网格 512×256 → 2048×1024**（`core/realearth.js#EARTH_RES`）。1024 宽时一格是 0.7°（约 78km），贴近到省级视野就是满屏大方块；2048 是 0.176°（约 20km）。取的正是高程源图 `earth-topology.png` 自己的尺寸——按它建栅格是 1:1 读图，一个像素不多不少；再往上源图里也没有更多信息，只会让 PNG 与导出文件一起发胖。**分辨率只留一个出处**：示例世界、菜单里的「生成真实地球」、工坊里的「真实地球」原先各写一个 512，现在都从这一个常量取，免得改一处漏两处。
2. **位移采样改双线性**（`view/globe.js#setRaster`）：`magFilter` / `minFilter` 由 `NearestFilter` 换成 `LinearFilter`（缩小过滤不能配 mipmap 档——`generateMipmaps` 是关的，那样会采到一张不完整的贴图，整颗球变黑）。高度是连续的场，最近点采样把每一格铺成一整块平地、格与格之间高度直接跳变。对 R+G 打包的 16-bit 高度无害：解包是两通道的线性运算，各自插值再解包与先解包再插值只差一次逐通道取整。**代价是工坊硬笔画的悬崖被磨掉一格**——原先「一格抬升 = 一堵垂直的墙」靠的正是最近点采样，现在那道墙变成了一格宽的斜面（赤道上约 20km 的水平距离）。这是要拿插值换锐利的地方，换算下来的取舍是：宁可墙软一格，也不要满屏方块。
3. **量了一下谁才是主因**。三张同机位截图（阿尔卑斯，相机距离 1.5，一格约 11 屏幕像素）逐像素比：512+最近点 → 2048+双线性，**平均通道差 5.7，20.5% 的子像素差过 8**；2048+最近点 → 2048+双线性，平均差 1.1，**3.2% 差过 8**。也就是说方块主要是**分辨率**消掉的，双线性是收尾——单换采样方式救不了 512 的格子，单升分辨率则会在格边留一层台阶。
4. **连带改动三处，都是分辨率的直接后果**：① 笔刷滑块上限跟着栅格宽度缩放（`ui/workshop-session.js#brushSizeMax`，512 宽时 48 格 = 2048 宽时 192 格），否则同一个「8 格」在新分辨率下盖住的地面只剩四分之一，像换了一支笔；落笔处再夹一次上限，兜住 store 里上一张网格留下的值。② 工坊白纸起步的画布同样改成 2048×1024，画到一半按「真实地球」不会突然换一档精度。③ 画布在适应窗口那一档从放大变成了缩小（拟合比例 0.588），`image-rendering` 不能再恒定 `pixelated`——最近点在缩小时会丢行丢列，让细线与色带抖成一片，现在只在放大档用最近点。
5. **实测代价**：成色 178 → **536ms**；PNG 0.13 → **1.61MB**（示例世界的 1.21MB，正是工单预估的 1–2MB 区间）；重新解码载入 26 → **238ms**；工坊一份撤销快照 0.6 → **10MB**（上限仍是 8 步，一份栈约 80MB）。对示例世界的载入（本就要下载并解码 369KB 高程图与河网）来说这些都在噪声里。
6. **验收**：`scripts/verify-terrain.mjs` 12 项全绿（珠峰采样由 0.74 升到 **0.94**——少了降采样的削顶），`scripts/ui-test.mjs` 45 项全绿，`npm run build` 通过，无运行时报错。

### v0.0.6 地图展示优化（2026-10-15）

1. **地点不再是一个圆点，而是印在地图上的地名**（`view/markers.js#LabelLayer`）。原先地点与事件都是一枚 Sprite：它永远正对相机，看上去浮在球前面，球上内容一多就成了一片浮标。现在每条地点是一块**贴合球面的四边形**，局部 +Z 对齐地表法线、+X 指向东、+Y 指向北——字横着读、字头朝北，随地球一起转，转到背面被球挡住，也就是「印在世界地图上」的样子。朝向不能只把 +Z 对上法线：那样还差一个绕法线的自转，字会是歪的，所以要把「东」和「北」也算出来凑成一个完整的基（`surfaceQuaternion`，极点处「东」塌成零向量时兜一个方向免得算出 NaN）。字号按屏幕像素算，与真实地图一样不随远近缩放。
2. **地名按视角淡出 + 逐帧贪心碰撞剔除**。字贴地就一定会在斜看时被压扁，所以按表面法线与视线的夹角余弦给不透明度：正对最清楚，越斜越淡，低于阈值整个隐掉——不留一条糊掉的横线。地平线以下先按 `dot(法线, 相机方向) > 1/相机距离` 剔一遍，剩下按正对程度从高到低做一次贪心，压住别人的让位。于是「拉远拉近」变的只是有多少地名挤得下，字体大小始终一致。这几件事**只跟相机有关、跟内容无关**，所以放在渲染循环里逐帧现算，不进 store。
3. **拾取改走屏幕空间**。贴合地表的四边形斜看时几乎侧对镜头，射线很难打中，于是会「正对着的点得中、边上的点不中」。改成拿每帧留下的屏幕落点与半宽半高直接查点（`markers.js#pick`），也就是真实地图那一套——按要素几何的投影查点，不靠字形本身。落点同时压住两块时取更近的那块；被碰撞剔除的地名不在候选里。点地名即选中它，球外的空白点一下则取消选中。路线与区域仍走射线，它们浮在地表之上。
4. **事件在球上不再铺点，只留选中那一条的光点**（`markers.js#EventDotLayer`）。整层就一枚 Sprite，跟着选中的事件走：选中一条有坐标的事件，那个坐标亮起一点；改选别的，它灭掉。光点按屏幕像素保持固定大小，用 Sprite 而不是贴地四边形——贴地的点在球缘会侧成一条线，而「此刻在这里」的提示任何时候都该看得见。颜色是统一的暖白旧铜色，不用随机彩色。
5. **删掉回放引擎**（原 `ui/playback.js`、`tl-play` 按钮、`store/ui.js#playing`、`api.js#play/stopPlay`）。事件改为只允许手动点开看。动手前先确认过：`flyToLatLng` 在 `view/camera.js`，与回放引擎完全无关，「飞到」「🎯 定位」、点刻度跳事件都走 `flyToItem → flyTo → rig.flyToLatLng` 这一条，删掉引擎一条都不受影响（`camera.js#onUserInterrupt` 用的是可选调用，降级成空操作）。
6. **◀ ▶ 一次翻一条事件，并且同步换掉选中**（`core/timeline.js#nextTickEvent` + `store/world.js#stepCursor`）。落点是**事件**而不是年份：点刻度与按箭头从此是同一件事，走同一条 `jumpToEvent`——设游标、选中、把镜头带过去一起做完，于是不会再出现「按了右箭头，检查器里还是上一条」。同一年里挤着好几条时按选中那条在刻度清单里的**位置**前后挪一条；游标已经被拖到别的年份就退回按年份找，否则会从选中事件那里接着跳、与眼前的游标对不上。
7. **同一年内不再按 id 排序**（`timeline.js#timeTicks` 去掉 `localeCompare` 兜底）。同一年的事件保持它们在数组里的先后，也就是**录入的先后**——它决定箭头先翻到谁。原先是按 id 字符串排的，而 id 是随机生成的，等于把作者排好的叙事次序打散了；`Array#sort` 本身就稳定，去掉这层兜底即可。
8. **示例世界彻底一战化**（`core/sample.js` 重写）。删掉亚特兰蒂斯、长安西市、君士坦丁堡、罗马帝国疆域、丝绸之路、四条旧事件，以及自动导入的 51 座真实城市与那座人工隆起的高地——舞台只剩真实地球高程这一张脸，叙事只落在 1914–1919 这六年里，事件密度从 5 条提到 **32 条**（萨拉热窝的那一枪到凡尔赛宫的签字），地点 19 处、人物 16 位，外加施里芬计划进军路线与西线战壕带。地点只写起始年，游标扫过去一个接一个浮出来。
9. **载入项目后镜头自动对准内容**（`store/actions.js#aimAtContent`）。初始视角是画面设置里写死的经纬度，而内容在哪完全是另一回事：示例世界全在欧洲，初始视角却在亚洲，载入后只看得到一片空球。现在 `loadProjectInto` 会把所有带坐标内容（地点、事件、路线的途经点、区域的顶点）的方向先转成三维向量再平均，飞过去。**必须在三维向量上求平均**——直接在经纬度上取平均，跨换日线时会得出一个荒唐的结果；内容绕球撒了一圈、平均值缩回原点时则不动镜头。只在载入新世界时做，页面刷新恢复上次的项目不动镜头，那是用户自己转出来的位置。
10. **画面设置**里的「标注」组改名「📍 地名与事件」，两项滑块变成「地名字号 px」与「事件光点 px」。
11. **验收**：`scripts/ui-test.mjs` 45 项全绿（含新增的点地名即选中、点空白取消选中、选中事件亮光点 / 改选即灭、◀▶ 逐条翻事件并同步选中、载入后镜头对准内容；删掉回放相关的 4 组），`scripts/verify-terrain.mjs` 12 项全绿，`npm run build` 通过，无运行时报错。

### v0.0.4 一根游标、事件层与回放（2026-10-14）

1. **时间模型推倒重来：删除「时间点」，换成一根数值游标**。原先世界是「时间点序列」，底图沿轴向上继承，每条内容挂 `from/to` 时间点 id。这带来两个绕不过去的问题：底图被绑在了时间上（球只有一张脸，底图凭什么跟着年号换），以及内容是第几个槽位上的东西、轴的长度要人手工维护。现在舞台与叙事彻底分开——`project.baseRasterId / baseMapId` 是项目级的**一张脸**，与时间无关；内容的 `from/to` 是**数值年**（负数 = 公元前，允许小数），两端留空 = 该端开放。轴的**定义域由内容自己算出来**（`core/timeline.js#timeDomain`），填一条带年份的内容轴就长一截，清空就缩回去，没有任何需要人维护的槽位。
2. **拖游标是零重建的**。有一条设计约束先说清楚：一条内容的样子是**它自己数据的纯函数**，永远与游标在哪一年无关。所以 `bridge.js` 拆成三件事——`rebuildLayers()`（内容变了，重建贴图与几何）、`applyActiveLayers()`（游标走了，只翻 `visible`）、`relayoutLayers()`（只是脚下地形变了，重新贴地）。实测连续 400 步推游标共 19.2 ms（0.048 ms/步），Sprite / 材质 / 纹理 UUID 全程不变。`raycaster` 不理会 `visible`，所以各层的 `pick` 自己筛一次。
3. **新增事件层**（`view/markers.js` 起第二层实例 + `project.events`）：事件与地点外形完全一样（Sprite 标注 + 配图 + 存续区间），差别有两条——事件**可以没有地点**（纯叙事事件不上球，只进编年史），以及事件是**时间轴刻度的来源**。
4. **底部时间轴重写**（`ui/react/Timeline.jsx`）：一条按时间线性铺开的数轴 + 一根可拖的游标，刻度由事件自己的年份落位；点在刻度上就跳到那一年。轴上不铺标题（挤在一起没法看），改为在读数区报出「游标之前最后发生的那条事件」。
5. **新增编年史长卷与回放**：`ui/react/Chronicle.jsx` 把全部事件按时间铺开成一条可横向滚动的长卷（没有地点的事件也在，标注「无地点」），跟着游标亮到哪读到哪；`ui/playback.js` 替人推游标，开播先把镜头拉到最远作开场，事件登场时在球上闪一下（`MarkerLayer#pulse`，只改缩放、不碰贴图），有地点的把镜头带过去。**运镜与用户输入互斥**：用户一拖球面，`CameraRig#onUserInterrupt` 通知回放让出镜头，游标照旧往前走。
6. **修复 `TweenManager` 的重入缺陷**（`utils.js`）：`update()` 原先就地 `filter` 自己的数组，而回调里可以再开动画（回放推游标 → 游标一走就 `flyTo`）。新加的这次飞行在数组里写下后又被外层 `filter` 收尾时整个覆盖掉、**凭空消失**，被它顶掉的旧动画反而复活并一路跑完。同一个坑早就存在：用户拖拽打断 `flyTo` 时若正赶上一帧，那次取消同样会被回滚。改为先把待办挪出来、算完再收回，取消用 `dead` 标记传给还在手上的那批。
7. **v1 项目自动迁移**（`core/migrate.js`）：时间点按序号变成事件（它本来就是「那个时刻发生的事」），逐时间点的底图取最后一个——也就是「世界演进至今的样子」，与打开项目时游标停在最后一年是同一个道理。`PROJECT_VERSION` 升到 2，`normalizeProject` 见到 v1 自动迁移。**内容一条不丢**，唯一真正丢掉的是逐时代的底图与地形。
8. **世界概览改挂「舞台」区块**：底图 / 地形 / 真实地球那组入口从时间点编辑器搬到世界概览，与时间无关；概览里那张「时代配图」**一并删掉**——概览讲的是整个世界，不是某一刻。配图这个能力下沉到地点与事件，两者沿用同一套控件。
9. **措辞清扫**：「条目」→「地点」（事件与地点是两类东西，不该共用一个含混的词），「切面 / 时间点」→「游标 / 在场」。
10. **验收**：`scripts/ui-test.mjs` 24 项全绿（新增长卷、回放推进零重建、暂停、收尾、镜头跟飞、跟拍让位）、`scripts/verify-terrain.mjs` 11 项全绿（含「拖游标不换脸」：`(5,20)` 处地形在公元前 9550 年与 1600 年完全一致）、v1 → v2 迁移双路验证、`npm run build` 通过、无运行时报错。

### v0.0.3 工坊视口、时代插图与自由翻滚（2026-10-13）

1. **笔刷可以小到一格**：工坊画笔下限由 2 格放到 1 格。1 格不能沿用原来「距离 ≤ 半径」的判据——正交四邻的距离恰好也等于整数 1，会被一并圈进来，落成一个十字形的 5 格；改成 `radius <= 1` 时只命中指针所在的那一格（`core/raster.js#applyBrush`）。
2. **工坊画布可滚轮缩放与拖动平移**（`ui/workshop-session.js`）：滚轮以光标为锚点缩放（光标底下那一格保持不动），中键 / 右键 / Shift+左键拖动平移，顶栏加缩放读数与「⤢ 适应窗口」。画布不再靠 `object-fit: contain` 铺满，改为原尺寸 + CSS `transform`，缩放倍数 1×（适应窗口）到 32×；外层新增 `.wk-stage` 负责裁切，`ResizeObserver` 在窗口变化时重算适应比例并让容器中心那一格留在原地。
3. **时间点可挂一张配图**（`core/project.js` 的 `image` 字段）：做法与**条目配图完全一致**——世界概览里一个「⬆ 上传配图」，有图则显示图片与「移除配图」。配图属于时代，跟着切面走；它与「贴到球面上的底图」是两回事，渲染管线完全不读它，随项目一起保存与导出。
4. **相机可以任意方向翻滚**（`view/camera.js`）：原先的轨道相机受 OrbitControls 球坐标限制——`phi` 由 `acos` 导出、恒在 `[0, π]`，到极点就被夹死（实测从 88° 出发连续五次同向拖拽都停在 90.000）。改为自己用四元数做 trackball，拖动时同时旋转相机位置与 `up`，于是能越过南北极、把地平线转歪；缩放仍交给 OrbitControls。自转改为绕世界 Y 轴（南北极）而非相机上方向，`main.js` 传入真实秒数使帧率高低转速一致。新增 🧭 复位视角（`world.resetView()`）。
5. **项目菜单移除「导入真实城市」**：下拉菜单不再暴露这一项；`world.importCities()` 与时间点编辑器里的导入按钮保持不变。
6. **验收**：`scripts/verify-terrain.mjs` 与 `scripts/ui-test.mjs` 全绿、无运行时报错；`npm run build` 通过。

### v0.0.2 海陆掩膜与三处卡顿修复（2026-10-13）

1. **新增可选的海陆掩膜** `core/landmask.js` + `public/textures/earth-water.png`：二值「是陆是海」场（外扩 1 格抹掉图上的细河线、保住沿海城市），另提供 `distanceToLand()` 倒角距离变换，供海洋深浅推导使用。
2. **高程与海陆解耦**：`core/raster.js` 只管「多高」，`core/landmask.js` 只管「是陆是海」，两者互不认识；`core/realearth.js` 才把它们拼起来。掩膜是**可选的**——自定义世界不必有它，没有掩膜时按高度正负判海陆，与旧行为一致。不再为了真实厚度升级整个高程系统，现有视觉立体效果原样保留。
3. **修复城条目落水**：原实现用高程图亮度配 `seaLevel=0.04` 判海陆，上海 / 开罗 / 伦敦这类低海拔城市（源图上是纯黑像素）全部被判成海洋。改由掩膜裁定后，示例世界 50 个条目**全部落在陆地上**（改前 38 个在水里）。
4. **修复时代切换卡顿**：真根因是着色器被反复重新编译——three 用引用计数管 GL 程序，整层重建时把旧材质 `dispose()` 会让程序一起销毁，下一帧又得重新编译链接（实测单次 `getProgramInfoLog` 275ms）。新增 `view/material-bin.js`，退下来的材质进桶复用；`view/globe.js` 换底图不再置 `sphereMat.needsUpdate`；`bridge.js#applyEra` 加 `{project, key}` 幂等闸（一次 `setTime` 原会触发 2–3 遍）；另加 `bridge.js#preheatEras` 在空闲时预解别的时间点的底图。改后：切换那一帧**主线程长任务为 0**（改前每切一次 1 个 100ms+ 长任务）。
5. **修复地形编辑卡顿**：工坊画笔与 `world.paintTerrain()` 都不再全量重建图层，改为只重定位（`bridge.js#relayoutLayers`，store 侧新增 `layoutEpoch/touchLayout` 区分「内容变了」与「只是地形变了」）。`paintTerrain` 也不再走 `mutateProject`（它会连带重建 `derived` → 50 张标注贴图全部重画），并按画笔返回的脏区重绘色带而非整张全量。改后：工坊画布拖 30 点长帧 0（改前 32 个，最长 158ms）；脚本接口刷 30 笔长任务 870ms → ~200ms（剩下的是 PNG 编码与纹理上传本身）。
6. **修复条目/路线被地形挡住**：改为一帧三趟渲染（`view/render-layers.js` 定义 `LAYER_SCENE / LAYER_MASK / LAYER_CONTENT`）：① 球体/大气/星空 → ② 半径 1 的光滑球只写深度不写颜色 → ③ 条目/路线/区域对着②的深度做测试。于是山挡不住内容，转到球背面仍会被正确挡住（正面可见 29 个全部可拾取、背面 21 个一个都拾不到）。
7. 顺带修复示例世界「亚特兰蒂斯高地」跑到南半球：`core/sample.js#atCell` 用 `res` 当作纬度方向格数，实际纵向格数是横向的一半。
8. 图片读取搬到 `utils/files.js`（`loadImage`），栅格与掩膜各自取用，互不依赖。
